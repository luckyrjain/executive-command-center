# Today Page Rebuild: Design

**Sub-project 5 of the "Calm Executive Workspace" redesign.** Foundation tokens (1), Navigation (2), Composition philosophy (3), and Action hierarchy and icons (4) are merged.

Note on numbering: DESIGN.md's Provenance section also uses "sub-project 3"/"sub-project 5"/"sub-project 6" for items in the earlier, separate Visual Foundation v2 six-part decomposition (Foundation, Navigation, Today's IA, card system, inspector/drawer, mobile pass) — a different list than this one. This document is sub-project 5 of the Calm Executive Workspace direction specifically; it is not the "sub-project 5 (inspector/detail drawer)" already closed under the older numbering.

## Why this exists

The original brief for this sub-project was "Today page rebuild," with no further detail. Checked against the live page and the real backend behavior before designing (not just the fixture data an e2e scenario happens to use), one part of a hypothetical full rebuild was already done and two real, unaddressed problems were found.

**Already done, not reopened here.** A 2026-09-04 fix (DESIGN.md's Morning Brief section, and its Known follow-ups line "No single dominant anchor on the Today dashboard — done") already removed the page's most obvious defect: `MorningBrief.tsx` used to re-render the same four `Section`/`.dashboard-card` panels the live dashboard grid already showed, so Schedule/Priorities/Overdue/Risks each appeared twice, item-for-item, with no visual cue distinguishing "live" from "persisted." That fix replaced the duplicated sections with `.brief-stats`, a compact `<dl>` of counts, and DESIGN.md recorded the anchor problem as closed.

**Two real problems remain — the second one only surfaces once you check what the counts do with real data, not just the fixture:**

1. **Two panels compete for the page's one dominant anchor, and the wrong one currently wins — so the 2026-09-04 fix was necessary but not sufficient.** `TodayPage.tsx:54-65` renders "Top priorities" first (`Sections.tsx`'s `variant="panel"`, which is the promoted `.work-panel` DESIGN.md calls the page's single dominant anchor), then `<MorningBrief />` (`:65`), then `.dashboard-grid` (`:67`). `MorningBrief.tsx` renders as `.brief-panel` — solid `--color-ink` fill, a `--text-display-sm` heading (`styles.css:293-301`) — visually louder than Top priorities' white card. DESIGN.md's own Hierarchy rules already name this exact failure mode: "if a new page has two `.work-panel`s of equal size fighting for attention above the fold, that's the tell something needs to be demoted" — Morning Brief isn't literally a `.work-panel`, but it produces the identical effect the rule warns about. Morning Brief is semantically a data-freshness status artifact (is this stale, is AI on, when was it generated) — Page anatomy's zone 4 ("secondary zones... visually quieter"), not zone 3. It is currently styled as if it outranks zone 3, which is why the Known follow-ups line calling this "done" needs correcting, not just the CSS.
2. **`.brief-stats`'s counts don't just duplicate the live badges — they can actively disagree with them, because the two sides count differently.** In the app's own e2e fixture, the brief's `sections` payload is set equal to the live dashboard's `defaultDashboardSections` (`e2e/fixtures.mjs`), so the two sides' counts happen to match there — but that's an artifact of the fixture, not a property of the real system. The backend inserts `{"empty": true, ...}` placeholder rows for an empty category (`backend/ecc/domains/platform/dashboard_briefs.py`), and the live dashboard's `Section` component filters those out before counting (`Sections.tsx`'s `visibleItems()`, called at `:87`), but `MorningBrief.tsx` counts the raw array length directly (`sections.today_schedule?.length ?? 0`, `:66`, `:70`, etc.) with no such filter. On a day with nothing scheduled, the live Schedule badge reads 0 while the brief's Schedule stat reads 1 — the two numbers don't just repeat each other, one of them is wrong. A stale, unrefreshed brief snapshot can diverge from live data for the same underlying reason (it's yesterday's counts, unfiltered). Removing `.brief-stats` fixes a duplication problem and a correctness problem at once.

## Scope decisions (from brainstorming)

- **Investigate and fix the verified problems, not a ground-up redesign.** Matches the discipline sub-project 3 (Composition) established: don't rebuild what already works.
- **Approach: demote Morning Brief to a quiet, borderless status row and remove `.brief-stats` entirely.** Its only remaining unique content — generation number, AI status, staleness, and the Refresh action — needs no card treatment of its own; when nothing is wrong, there's nothing to visually enclose. When something IS wrong (stale, error, AI disabled), the app's existing `.inline-status`/`.error-panel`/`.degraded-panel` classes already render that specific message in its own bordered box (the same pattern `TodayPage.tsx:45-52` uses for the live dashboard's own loading/error/stale states). Two alternatives were considered and rejected:
  - **Give the outer wrapper its own border/fill too, matching `.status-panel`'s look.** Rejected after checking `.inline-status`'s actual CSS: it has the identical border, radius, background, and padding this alternative would give the wrapper (`styles.css:216-226`). Any `.inline-status` banner rendered inside it (the stale/AI-disabled/error messages already in `MorningBrief.tsx`) would be a box nested inside an identical box — precisely the pattern DESIGN.md's Hierarchy rules forbid ("don't nest bordered panels inside bordered panels") and Anti-patterns lists as "a card inside a card." Borderless avoids this outright rather than needing an override to flatten the inner banners.
  - **Keep the dark hero panel but move it below the dashboard grid.** Rejected: still visually heavy wherever it lands, and doesn't address that the panel's remaining content doesn't need hero treatment at any size.
  - **Fold Morning Brief into the page's topbar caption, removing it as a separate element entirely.** Rejected: a stale-brief "Refresh" action deserves its own visible control, not a buried caption line.
- **`Sections.tsx`, `.dashboard-grid`, `.dashboard-card`, and Top priorities's own styling are untouched.** The fix is Morning Brief's presentation only. (`Sections.tsx`'s own header comment still describes Morning Brief as rendering `Section`s, which predates the 2026-09-04 fix and is already stale — real, but pre-existing and out of scope here; not introduced or worsened by this change.)
- **No backend or data-shape change.** `MorningBriefResponse` is unchanged; this is a frontend rendering decision on data already fetched. Fixing the backend to filter placeholder rows itself, so `.brief-stats`-style counts could someday be trusted, is a real option but out of scope — removing the count display is the immediate fix.

## Design

### 1. `MorningBrief.tsx` — restructure, no new data dependency

Remove the `<dl className="brief-stats">` block entirely (four `<dt>`/`<dd>` pairs and their surrounding markup). Nothing else in the component's data flow changes: the same `useQuery`/`useMutation` calls, the same loading/error/AI-disabled/stale conditionals, the same "Refresh brief" button.

Change the wrapping element's class from `brief-panel` to `brief-status`, and the heading block's class from `brief-heading` to `brief-status-heading` (new names — `.brief-status` is no longer a bordered panel at all, so keeping `.brief-panel`'s name would misdescribe it to a future reader). The heading's `<h2 id="morning-brief-title">Morning Brief</h2>` and its description `<p>` stay exactly as they are — same text, same conditional generation/AI-status string — only their surrounding class and resulting size change.

### 2. CSS — `.brief-status` is borderless; reuse the existing heading-row layout instead of duplicating it

Delete these rules from `styles.css`, exactly as they exist today: `.brief-panel` (`:293-299`), `.brief-heading` (`:300`), `.brief-heading h2` (`:301`), `.brief-heading p:not(.eyebrow)` (`:302`), `.brief-heading .eyebrow` (`:303`), `.brief-panel button` (`:304`), `.brief-panel .inline-status` (`:305`), `.brief-stats` / `.brief-stats dt` / `.brief-stats dd` (`:307-309`).

`.brief-heading` is also a member of a **shared, non-media rule** at `styles.css:150-155` (`.topbar, .brief-heading, .recommendation-heading, .explore-heading, .work-heading { display: flex; align-items: flex-start; justify-content: space-between; gap: 24px; }`) — do not write a new standalone flex rule for `.brief-status-heading`; that would duplicate this one verbatim. Instead, **replace `.brief-heading` with `.brief-status-heading` as a member of this existing list.** The row layout (heading left, button right, wrapping on narrow widths) comes from this shared rule for free.

Add only the two rules this shape still needs beyond that shared layout — the outer wrapper's spacing (no border, no fill) and the smaller heading size:

```css
.brief-status { margin-top: 36px; }
/* h2 size/tracking matches .section-heading h2 exactly (var(--text-lg),
 * -.01em, styles.css:248) -- the same "quiet section heading" precedent
 * already used elsewhere (e.g. AttentionQueue's grouped headings), not a
 * new size. */
.brief-status-heading h2 { margin: 0; font-size: var(--text-lg); letter-spacing: -.01em; }
.brief-status-heading p:not(.eyebrow) { margin: 6px 0 0; color: var(--color-text-secondary); }
```

`.eyebrow` needs no new rule — the existing shared `.eyebrow` rule (`--color-text-secondary`) already applies once the dark background is gone. `.inline-status`/`.error-panel`/`.degraded-panel` need no override at all: with no outer box, each status message keeps rendering as its own single, un-nested bordered banner, exactly like `TodayPage.tsx`'s own dashboard-level status messages already do. The plain `button` rule now applies to "Refresh brief" unmodified, matching every other page's default button.

**Bottom spacing before `.dashboard-grid`.** The old `.brief-panel` had no `margin-bottom`; its padded box happened to sit flush against the grid below. With the border and fill gone, a bare text row sitting flush against the grid's bordered cards is likely to read as a layout mistake, not a deliberate quiet design — the grid's own internal rhythm is an 18px gap (`.dashboard-grid`'s `gap: 18px`, `styles.css:234`). Add `margin-bottom: 20px` to `.brief-status` (matching `.status-panel`'s own bottom-margin value, `styles.css:225`, for consistency with the app's other status-row spacing) as a starting value, and confirm it visually in verification rather than trusting this number sight-unseen — adjust to what actually looks right against the real screenshot if 20px reads as too much or too little next to the grid's 18px internal gaps.

**Mobile breakpoints — two separate lists need `.brief-status-heading` added, and two need `.brief-heading`/`.brief-panel` removed.** At `@media (max-width: 520px)` (`styles.css:786-799`):
- The flex-column list (`.topbar, .brief-heading, .recommendation-heading, .explore-heading, .work-heading { align-items: flex-start; flex-direction: column; }`): remove `.brief-heading`, add `.brief-status-heading`.
- The button-padding list (`.topbar button, .brief-heading button, .recommendation-heading button { padding: 9px 14px; }`): remove `.brief-heading button`, add `.brief-status-heading button` — without this, "Refresh brief" would keep its full 11px 18px padding at narrow widths while every other heading-row button in the app shrinks, which is inconsistent with the "same shape as the others" reasoning for adding this element to the flex-column list in the first place.
- The border-radius list (`.brief-panel, .recommendation-panel, .explore-panel, .work-panel { border-radius: 12px; }`): remove `.brief-panel`. `.brief-status` has no border-radius rule at all now (it's borderless), so nothing needs to replace it here.

This repo just landed a dedicated fix for narrow-viewport heading-row overflow (`fix(frontend): wizard stepper no longer overflows the page at 320px`, #274) — see Verification below for extending that fix's own automated check to cover this element too, rather than relying on a manual look.

**Token cleanup.** `--color-border-on-dark`, `--color-text-on-dark-muted`, and `--color-text-on-dark-faint` (`styles.css:27-29`) have no consumer anywhere in `frontend/` outside the rules being deleted above — verified by grepping the whole tree, not just `styles.css`. Delete all three token definitions; leaving them defined-but-unused would pass `check:tokens` (which only checks that referenced tokens resolve, not that defined tokens are used) but would be dead weight.

### 3. Placement — unchanged order, demoted weight

`TodayPage.tsx`'s JSX order stays exactly as it is: Top priorities, then Morning Brief, then the dashboard grid. Reordering was considered and rejected: Morning Brief's new compact, borderless treatment is quiet enough that it no longer competes with Top priorities for "first dominant thing on the page" regardless of position, so moving it adds a diff for no verified benefit. Top priorities remains the true first thing rendered when present; Morning Brief now reads as a short status line between it and the grid, consistent with Page anatomy's zone 4.

### 4. Tests

**`MorningBrief.test.tsx` has 6 tests today; 5 survive unchanged, 1 is replaced.** The five that need no test-logic change: `'refreshes via POST with CSRF and idempotency headers'`, `'clears the stale banner and reflects the refreshed generation number'`, `'shows an AI-disabled notice distinct from the stale/error states'`, `'does not show the AI-disabled notice when AI is available'`, and `'keeps the current brief visible and reports a recoverable error when refresh fails'` — each asserts against text and roles the restructure preserves (`Generation N`, `role="alert"`, the "Refresh brief" button's accessible name), but every one must still be re-run to confirm, not assumed.

`'renders a compact count per brief category instead of duplicating full item lists'` and its `statValue()` helper are removed — the behavior they assert no longer exists by design. Replace with a test that keeps this file's original duplication guard rather than dropping it: render the same populated fixture used by the removed test (non-empty `today_schedule`/`top_priorities`, empty `overdue_commitments`/`risks`), **wait for the brief to actually load first** (`await screen.findByText(/Generation 1/)` — without this, a `queryByText(...)` check can run before the fetch resolves and pass vacuously, since nothing has rendered yet either way), then assert `screen.queryByText('Schedule')`, `screen.queryByText('Priorities')`, `screen.queryByText('Overdue')`, and `screen.queryByText('Risks')` are all `null`, and keep the original test's `expect(screen.queryByText('Board sync')).toBeNull()` (the one direct check that item-level duplication hasn't crept back in).

**`frontend/e2e/scenarios/dashboard-brief.mjs` needs a real edit, not just a re-run.** Its `briefPanel` locator (`section[aria-labelledby="morning-brief-title"]`) survives unchanged — that id stays on the same `<h2>` — but lines 58-62 locate `.brief-stats` and assert on its four labels; as written today this scenario would fail after the change, not merely need re-running. Delete those five lines. Restate (don't just delete) the comment immediately above them (lines 53-57), which documents the original item-level duplication problem — that reasoning is still relevant context for a future reader of this file, now extended to cover why the counts are gone too, not just the items. Consider adding one negative check in their place — e.g. `assert.equal(await briefPanel.locator('dl').count(), 0, 'the brief should not render a stats dl')` — so a future regression that quietly reintroduces a stats block is caught here, not just in the unit test. No other e2e scenario file references Morning Brief's structure (checked across `frontend/e2e/`); the scenario's other assertions (`Generation 3 · disabled`, the AI-disabled and stale banner text, the post-refresh `Generation 4` check) are unaffected by the class/size change.

**Extend the automated 320px overflow check (`frontend/e2e/scenarios/layout-integrity.mjs`) to cover `/today`, as a new standalone check, not a new member of the existing loop.** The scenario's existing 320px loop (`for (const path of ['/risks', '/schedule'])`) waits for `.wizard-stepper` before asserting zero horizontal overflow — `/today` has no wizard stepper, so adding it to that loop would hang waiting for an element that never appears. Add a separate block directly after that loop and the `/automation` tab check, at the same already-set 320px viewport: navigate to `/today`, wait for `.brief-status-heading` (an element this spec's own change introduces, so this check also doubles as a smoke test that the new markup renders), then assert `horizontalOverflow(page)` is `0`, matching the existing assertions' own message style (`` `${path} must not scroll horizontally at 320px` ``).
